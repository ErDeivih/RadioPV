# 🎨 RadioPV · Diseño de la interfaz (UI)

> **ESTADO REAL (2026-08-30):** La UI web está implementada como SPA en `frontend/` (React 19 + Vite + antd),
> con la capa adaptadora de `api/adapt.ts` traduciendo nuestros endpoints a la forma que espera la UI (hereda
> de un cliente tipo Spotify). Documento de diseño: las secciones que siguen describen el plano; el estado
> vivo está en [`PROGRESS.md`](PROGRESS.md) y la cola de trabajo en [`ORDEN_DE_TRABAJO.md`](ORDEN_DE_TRABAJO.md).
> En móvil se usa la **PWA instalable** (ver [`07_CROSS_PLATFORM_BLUEPRINT.md`](07_CROSS_PLATFORM_BLUEPRINT.md)),
> no una app nativa.

> Orientativo para una **SPA (React + Vite + Tailwind)** tipo Spotify. Si se decide usar Streamlit,
> las secciones son análogas con sus componentes.

## 2. Páginas
- **Inicio / Para ti**: saludo; filas de tarjetas → "Recomendadas para ti", "Daily Mix 1/2/3",
  "Trending", "Novedades", "Radar de nuevos", "Tus artistas".
- **Buscar**: barra con **autocompletado** (FTS) + chips de faceta (género, era, mood, energía, idioma)
  + cuadrícula de resultados (tarjetas con carátula).
- **Biblioteca**: canciones guardadas, álbumes, artistas seguidos, descargas; filtros.
- **Playlists**: lista (user + automáticas) y detalle (portada, nº, reproducir/aleatorio, tracks,
  añadir/eliminar, reordenar).
- **Artista**: cabecera (foto, nombre, fans), discografía, top canciones, relacionados, "radio".
- **Álbum**: portada, año, pistas.
- **Radio / Mix**: seed → reproducción sin fin de temas parecidos.
- **Stats / Wrapped**: hábitos, top artistas, minutos, evolución.

## 3. Componentes (design system)
`Sidebar`, `TopBar`, `SearchBar(autocomplete)`, `Card(cover,title,subtitle,playOnHover)`,
`PlaylistCard`, `TrackRow`, `PlayerBar`, `QueuePanel`, `ProgressBar(seek)`, `VolumeSlider`,
`IconButton`, `PrimaryButton`, `Badge`, `Spinner/Skeleton`, `EmptyState`, `Toast`, `Dialog(addToPlaylist)`,
`SegmentedControl(facetas)`.

## 4. Estados por vista
Cargando (`Skeleton`), vacío ("no hay resultados"), error (`Toast`), offline.

## 5. Flujo de reproducción
1. Pulsar ▶️ en tarjeta/fila → `POST /play` + añadir a **cola**.
2. **PlayerBar** muestra cover/título/controles; **queue** gestiona siguiente/anterior.
3. 👍👎 → `POST /library/{track}/like|skip` → alimenta perfil/mixes.
4. Abrir playlist/radio → cargar `tracks_json` (mixes precomputados).

## 6. Responsive y accesibilidad
- Móvil: player minimizado. Teclado/focus, contraste, aria-labels.

## 7. Sobre el estilo visual
- **Tema oscuro** tipo Spotify, acento verde/el que configures. Carátulas/fotos **locales** (`cover_path`)
  para carga rápida. Tipografía limpia y jerarquía clara.

---

## Notas para el agente
- Consumir la **API** (`docs/02_API.md`); la UI es un cliente del backend.
- Las imágenes de **canciones** usar `cover_path`/`cover` (local) o `cover_url` (fallback). La foto del
  **artista** vive en la tabla `artists` (`image_path`/`image`) y se pide **por artista, no por canción**
  (`tracks.artist_image_path` está vacío). El backend ya expone `cover` (TrackOut) e `image` (ArtistOut).
- El **PlayerBar** debe registrar `record_play` y el estado de cola (estilo "contexto de Spotify"):
  la app reproduce la playlist/radio actual y permite "añadir a continuación".
